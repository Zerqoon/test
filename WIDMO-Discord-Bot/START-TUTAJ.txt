WIDMO — BOT DISCORD 3.0 👻

START NA RAILWAY
1. Wgraj zawartość folderu do repozytorium GitHub; Dockerfile ma być w katalogu głównym.
2. W Railway dodaj Variables: DISCORD_TOKEN, CLIENT_ID, GUILD_ID, DATABASE_PATH=/app/data/bot.sqlite. OWNER_IDS jest opcjonalne.
3. Dodaj Volume pod /app/data. Użyj jednej repliki, by nie uruchamiać dwóch kopii korzystających z tej samej bazy.
4. W Discord Developer Portal włącz Server Members Intent i Message Content Intent.
5. Deploy, następnie uruchom /widmo-setup jako Administrator.
6. Podałem do config.json ID Twoich kanałów welcome, poziomów, voice oraz wszystkich 4 grup logów. Bot sam opublikuje kartę informacji o poziomach.
7. /widmo-setup możesz uruchomić, by dokończyć brakujące elementy; wskazane ID kanałów zostaną zachowane. Sprawdź /konfiguracja i /powitanie-test.
8. Własny voice tworzy się po 5 s; panel jest w czacie kanału, a pusty pokój znika po 5 s. Logi voice trafiają do wskazanego kanału.
9. Przy starcie bot uzupełnia 3 wskazane role obecnym członkom i nadaje je nowym osobom.

SYSTEMY WIDMO 3.0
• Moderacja, automod, logi wiadomości/linków, voice, członków, użycia komend i zmian administracyjnych.
• XP, poziomy, ranking, karta graficzna i automatyczna karta informacyjna w kanale poziomów.
• Prywatne tickety z potwierdzeniem zamknięcia oraz transkryptem TXT.
• Role samodzielne poprzez przyciski — tylko role bez uprawnień.
• Propozycje społeczności z głosowaniem za/przeciw.
• Giveaway, prywatne pokoje głosowe, powitania i diagnostyka.

START LOKALNY
1. Wymagany Node.js 22.18+.
2. Skopiuj .env.example jako .env i wpisz token, Application ID oraz ID serwera.
3. W folderze projektu uruchom: npm ci, npm run deploy, npm start.

Rola bota musi być wyżej niż role, którymi zarządza. Nie udostępniaj tokenu, pliku .env ani bazy SQLite. Transkrypty zawierają prywatne treści — ogranicz dostęp do Archiwum Cieni.
Szczegóły: README.md i RAILWAY.md.
